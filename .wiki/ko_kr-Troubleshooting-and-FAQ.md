# 문제 해결 및 자주 묻는 질문

> 📌 **저장소 소스 코드 면책 조항**: 이 위키의 문서는 CurseForge 및 Modrinth의 공개 릴리스 빌드보다 앞선 최신 미출시 커밋 또는 개발 중인 기능을 포함할 수 있는 **저장소의 현재 소스 코드 상태**를 반영합니다.

## ❓ 자주 묻는 질문

### Q1: 기존 월드에서 `config/stack-size-adjuster.json`의 설정값이 적용되지 않습니다.
**A**: 전역 설정 파일은 **새로 생성되는 월드**의 초기 템플릿으로만 사용됩니다. 기존 월드에서는 설정이 `level.dat`에 저장되므로, 게임 내에서 `/gamerule` 명령어를 통해 조정하세요:
```text
/gamerule stack-size-adjuster:items_64_limit 256
```

### Q2: 스택 제한을 39,768,215보다 높게 설정하면 어떻게 되나요?
**A**: $39,768,215$를 초과할 경우 **대형 상자 정수 오버플로** 위험이 발생합니다. 54칸 대형 상자가 꽉 차면 부호 있는 32비트 정수 한도($2,147,483,647$)를 넘어서 음수로 바뀌고 아이템이 삭제될 수 있습니다. $\le 39,768,215$ 이하로 유지하는 것을 강력히 권장합니다.

### Q3: 상자를 부술 때 수만 개가 떨어지지 않고 8개 묶음만 나오는 이유는 무엇인가요?
**A**: 이는 서버 멈춤을 방지하기 위한 성능 최적화 기능(`stack-size-adjuster:max_drop_entities`, 기본값: `8`)입니다. **Item Clumps** 모드와 함께 작동하면 이 8개 묶음도 즉시 1개로 합쳐집니다.

## 🛠️ 일반 문제 진단

| 증상 | 원인 | 해결책 |
| :--- | :--- | :--- |
| **인벤토리가 바닐라 제한으로 표시됨** | 네트워크 패킷 전송 실패 또는 버전 불일치 | **클라이언트와 서버 양쪽**에 동일 버전이 설치되어 있는지 확인하세요. |
| **Give 명령어 실패: "아이템이 너무 많음"** | `/give` 수량이 $100 \times \text{maxStackSize}$를 초과함 | 요청 수량을 줄이거나 여러 번에 걸쳐 명령어를 실행하세요. |
| **ModMenu에서 YACL 화면이 열리지 않음** | ModMenu 또는 YACL 미설치 | 클라이언트에 **ModMenu**와 **YetAnotherConfigLib (YACL v3)**를 설치하세요. |
